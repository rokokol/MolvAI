Voice editing

Select a paragraph, say what to do with it

Select text, hold Ctrl+Alt+X, say the instruction and release. The selection is replaced with what the model returned: a translation, emoji, a shorter version, another tone. This is not dictation into a field, it is an edit of what is already written

Any application Replaced in place Local or cloud model

Examples

Three instructions, three results

An instruction is an ordinary phrase, not a command from a list. The model receives it together with the selection, so "translate to German", "add emoji" and "make it shorter" all work

SelectedHi, how are you? The call moved to tomorrow.

You saytranslate to German

The selection becomesHallo, wie geht es dir? Der Anruf wurde auf morgen verschoben.

SelectedThe call moved to tomorrow. Do not forget the documents.

You sayadd emoji

The selection becomes📅 The call moved to tomorrow. 📄 Do not forget the documents.

SelectedI looked at the task and I think we can finish it by Friday if nothing changes.

You saymake it shorter

The selection becomesWe will finish by Friday if nothing changes.

  1. Select the text

    Any text in any application: a paragraph in an editor, a message in a chat, a line in a terminal

  2. Hold the key and say the instruction

    Ctrl+Alt+X by default, and the combination is a setting. The daemon copies the selection through the compositor and sends the model the instruction together with the text

  3. Release, and the selection is replaced

    The result takes the place of the selection, and the phrase goes to the journal with the instruction and the model. If you do not like it, Ctrl+Z in the application brings the old text back

The rules

What the model receives and what it returns

The prompt is short and forbids almost everything a model likes to add. That is not decoration: without the ban a small model returns a document with headings instead of one translated line

The instruction first, the text second

The order matters: with the text first, a small model takes the fragment for the task and invents a document. So the request reads INSTRUCTION: … TEXT: …

The text only, with no wrapping

No headings, no markdown, no quotes, no explanations. The model adds no facts that the selection did not carry

The language changes only when told

Without "translate", the text keeps its language. With "translate to German", the whole selection changes, not the first sentence

Cannot apply it, returns it unchanged

The prompt tells the model to return the text unchanged when the instruction cannot be applied. So "make it shorter" on a single line does not turn into an invention

Your own prompt

command_mode.system_prompt replaces the built-in prompt for every language. An empty value keeps the built-in one, which speaks the language of the instruction

The dictation rules take no part

The instruction goes to the model as it is, because the cleanup rules would distort it. The dictionary and the rules apply to dictation, not to an edit of a selection

What it needs

A model and one key combination

Voice editing is the one feature that needs a model by definition: without one there is nothing to apply the instruction

[llm]
enabled = true
provider = "ollama"
model = "qwen3.5:4b"

[command_mode]
enabled = true
system_prompt = ""

[hotkeys]
command = "Ctrl+Alt+X"

The default provider is Ollama, that is a local model. A cloud provider works the same way, and its calls enter the model cost in the statistics

  • llm.enabled = true and a configured provider, local or cloud
  • command_mode.enabled = true, which is the default
  • hotkeys.command, Ctrl+Alt+X by default
  • A compositor that hands over the selection on Ctrl+C: Hyprland, Sway, KDE and GNOME, with a fallback to a virtual keyboard
molva config set llm.enabled true
Limits

What voice editing does not do

The limits below are properties of the design, not loose ends. Each one is named so you can rely on it

It needs a model

Without a model there is nothing to apply the instruction, and the command answers with an error rather than silence. Snippets, by contrast, work without a model: they are different tools for different jobs

The selection goes through the clipboard

The daemon copies the selection with Ctrl+C and reads the clipboard. It clears the clipboard before the copy, so a stale selection cannot be read, and waits up to 600 ms. So whatever the clipboard held at that moment is lost

The whole selection is replaced

An edit is never partial: the result takes the place of the whole selection. To fix one word, select one word

A long selection costs tokens

The selection goes to the model whole, so a paragraph costs less than a page. With a cloud provider the spend shows in the statistics as the model cost
