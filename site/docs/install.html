Install and first run

Canonical source: docs/install.md

The full guide is written as a prompt for an AI agent. Open an agent in the repository and say "read docs/install.md and install MolvAI". This page is the same path without the agent, in fewer words

Before you start

What the machine needs, by part
PartWhat to install
Build toolscmake, pkg-config, a C++ compiler, ALSA headers, libxkbcommon. ./install.sh --check prints the exact package names for Debian, Fedora, Arch, openSUSE, macOS and Windows
Wayland pastewtype and wl-clipboard
X11 pastexdotool and xclip
GUI onlyWebKitGTK, GTK 3, the AppIndicator library, librsvg. The CLI and the daemon do not need them
SoundPipeWire or PulseAudio. molva doctor names what it found

Install with Nix

Nothing enters the system. The flake gives a package, a dev shell and a Home Manager module

nix run github:rokokol/MolvAI -- --help
# a development shell with the toolchain and the system libraries
nix develop
cargo build --release --bin molva
./install.sh

With Home Manager the module installs molva and runs molva daemon as a user service of the graphical session. Under Hyprland with a Lua config it also writes and includes the hotkey binds

# flake inputs: molvai.url = "github:rokokol/MolvAI";
imports = [ inputs.molvai.homeModules.default ];
programs.molvai.enable = true;
# показать страницу настроек только для просмотра; запись всё равно запрещена
programs.molvai.showSettings = true;

In this mode the settings file and the weights are rendered into the store. The settings page explains what that changes

Install without Nix

The script installs nothing by itself. It finds the missing dependencies, prints the commands for your distribution, and leaves the decision to you

./install.sh --check

After you install what it lists, run the installer. The binary goes to ~/.local/bin and needs no administrator rights

git clone https://github.com/rokokol/MolvAI && cd MolvAI && ./install.sh

Check that ~/.local/bin is in PATH, then check the binary

molva --version

The installer can also create an autostart entry, and it removes what it installed through a manifest

./install.sh --autostart
./install.sh --uninstall --purge

Install from a release

The releases page carries a CLI archive for each system, an AppImage, a deb, a dmg and a Windows installer. Every file has a SHA-256 sum in sha256sums.txt

  • The Linux and Windows builds run whisper models through Vulkan, one build for NVIDIA, AMD and Intel. They fall back to the CPU when no Vulkan device exists, and the transcribe.cpp build in the flake keeps GigaAM on the CPU
  • The macOS build computes on the processor
  • The free packages sit apart from the CUDA archive, which carries the NVIDIA runtime and ships for Windows and Linux
Check the release notes for the GUI packages

The GUI packages of v0.1.0 shipped without the CLI, so the window asked you to build molva. If that happens, unpack the CLI archive of the same release and put the binary next to the application. The notes of the release you downloaded say whether the fix is in it

First run

  1. Run the diagnostics. They check the session, the compositor, the paste tools, the permissions, the daemon socket, the weights and the model provider

    molva doctor

  2. Choose the microphone from the list, then write its name to audio.device. A zero level while you speak means a wrong device or a muted channel, not a quiet voice

    molva devices

  3. Start the daemon. By default it downloads the GigaAM weights at start, shows progress in stderr and checks the SHA-256. You can pull them first instead

    molva models pull gigaam-v3-e2e-rnnt-q4_k_m
    molva daemon

  4. Put the cursor in a text field and check the paste. The command prints which method reached the field

    molva test-inject

  5. Attach the hotkeys. On Hyprland 0.55 and later the config is Lua, and one command writes the binds from your settings

    molva setup hyprland --write

    Then add the include line it prints to ~/.config/hypr/hyprland.lua, and reload Hyprland. On GNOME and KDE you add the same commands as custom shortcuts; on Windows and macOS the application registers the combination itself

macOS permissions

The system asks for microphone access, and the paste needs the Accessibility and Input Monitoring rights in the security settings. Without them the app runs and writes nothing into other applications

Where things live

WhatPath
Binary~/.local/bin/molva after install.sh
Settings~/.config/molva/config.toml, or the platform settings directory

WeightsThe default models directory, or stt.model_path when you set it
