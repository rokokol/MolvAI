Status and roadmap

Canonical source: docs/STATUS.md

MolvAI started at the V0ICE hackathon in Kazan in September 2026 and is in development. The repository has released v0.1.9, and the changes after that tag are in the Unreleased section of the changelog

This page is a signpost, not a second status file. The checkpoint log, the results of the checks and the cut list live in docs/STATUS.md, and the released changes live in the changelog

What works

  • End-to-end dictation: a key press opens the microphone, the text lands in the active field, the phrase goes to the journal
  • Hold, tap, toggle and cancel, with the default GigaAM-v3 model and the auto engine
  • Chunks recognized during the recording for the draft, with the field receiving one piece after the release
  • Text quality without a model, and an optional OpenAI-compatible model through Ollama or a cloud provider
  • Voice editing of a selected paragraph, which is command mode
  • Audio and video transcription with timecodes, and search over the resulting transcripts
  • A journal with statistics, optional encryption and keys in the OS store
  • A Nix flake and a Home Manager module that render the settings and the weights into the store
  • File transcription goes through the daemon: Files sends file.transcribe over IPC, and the model, the language, the dictionary and the rules are the ones dictation uses. molva transcribe stays a separate command for an offline batch
  • The window starts the daemon itself when a recording or a file needs it, with the same config and the same socket. The daemon is shared: quitting the window stops only the process that the window started
  • A file does not move the state: it sets job = file while the state stays idle, and the panel and molva status report a file transcription. A recording during a file is accepted and waits in the queue, and a file during a recording gets a busy answer that the window retries for up to half an hour
  • MCP is a stdio server with no port, URL or autostart: it starts the daemon when nobody answers and uses its model. mcp.enabled turns the server off. Six tools: transcription, search, statistics, history, the model catalog and a search over the documentation
  • A transcription through MCP is tagged MCP in History and in the panel, while one started from the Files tab keeps the Files tag
  • The settings page in the GUI: the recognition provider, the key source of each secret, custom styles, a hotkey recorder, a second request for the device list and an MCP section
  • A Snippets tab: a phrase and a ready replacement. A phrase that matches as a whole returns the replacement before the model, so a frequent reply neither waits for a call nor spends tokens. A * matches any text, and an exact phrase wins over a wildcard; a search filters the cards
  • Cloud model calls run up to four at a time, and local calls run one at a time. Phrase post-processing stays on the daemon worker; a style can ask the same model to translate the text
  • Vulkan recognition in the Linux and Windows builds, with a CPU fallback

What is not ready

  • Some live checks are still unverified, among them pasting in the Russian layout on Windows and opening the ad hoc signed dmg on a Mac. The current list is in docs/STATUS.md
  • CUDA archives ship separately for Windows and Linux. Linux and Windows compute through Vulkan in the main packages
  • Pre-roll audio is not captured, by design: the microphone must stay closed between phrases
  • The project publishes no GigaAM GPU benchmark: the repository's transcribe.cpp build is CPU-only. The figures on the home page are this project's own CPU measurements, not upstream
  • There is no long-term support promise. The project is a hackathon result that is being kept alive
  • Video preview and the audio spectrogram in Files are temporarily off: WebKit/GStreamer hung the window. The transcript, timecodes, search and opening the file still work
  • Live chunk typing is temporarily off: a phrase arrives as one piece after the release

Roadmap

The project publishes no dates. What comes next is the Unreleased section of the changelog, which lists the changes already in the tree. The "Next" line of each checkpoint in the status log says the same

  • Unreleased changes
  • Checkpoints and cut lists
  • Releases
  • Open issues
  • Set up journal encryption: enable journal.encrypt, keep the key in the OS store, and check that old entries still open
  • Find a local multilingual speech recognition model and choose the best option
  • Build a proper video preview in Files: player, codecs and timecode sync
  • Build a proper audio spectrogram in Files: decoding, memory and sync
  • Bring back live chunk typing without duplication or lost order
  • Add cloud speech recognition: an OpenAI-compatible STT client, a key in the OS store, an engine choice and a test button
  • Add LLM spending to statistics: per-model and per-provider token prices, with a day and month total
  • Optimize the GUI's memory use: measure the window's peak RSS, remove extra copies of history and media, and check that WebKit releases pages after a tab closes
  • Optimize the GUI's performance: measure GPU and VRAM at rest and while switching tabs, and remove constant animations and background layers that keep the video card busy
  • Make snippets the site's key feature: a screenshot of the tab and a dedicated block on the home page
The honest measure of a green run

The repository gates changes on just check, which runs the formatter, the linter, the tests, the dependency checks and the SPDX headers. The status log records the test count and shows the checks that were seen red before they turned green
