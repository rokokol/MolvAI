Hotkeys and compositors

Canonical source: docs/hotkeys-wayland.md

Why the compositor owns the key

On Wayland no application can take a global hotkey. The compositor owns the keyboard focus completely, and a key combination cannot be intercepted past it. That is a protection, not a gap. So the main control path is a compositor bind that runs molva record

The fallback reads /dev/input/event* through evdev and sees keys before the compositor does. It needs read permission on the input devices; on NixOS that means membership in the input group

The defaults

Values of the [hotkeys] section
KeyDefaultWhat it does
push_to_talkF9Records while the key is held
toggleCtrl+Alt+ZStarts and stops a recording by a press, hands-free
commandCtrl+Alt+XCommand mode on the selected text
cancelCtrl+Alt+CThrows the recording away without a phrase
style_nextCtrl+Alt+SThe next post-processing style in a circle
min_hold_ms200A shorter hold does not create a phrase
tap_togglestrueA short press latches the recording
short_press_ms250Below this, a press counts as a tap
double_tap_ms350A second press inside this window counts as a bounce

The default combinations are deliberately plain: F9 and Ctrl+Alt are free almost everywhere, so they work on a borrowed machine with no setup. Change them in ~/.config/molva/config.toml, not in the generated bind file

Hold, tap, cancel

Push-to-talk needs two events, the press and the release. Hyprland and Sway can send both. A hold shorter than min_hold_ms creates no phrase. A press shorter than short_press_ms with tap_toggles = true latches the recording, and the next press ends it

Hyprland 0.55 and later

Since 0.55 the Hyprland config is Lua. MolvAI writes its binds to a file of their own, and your config includes it once

molva setup hyprland --write
-- ~/.config/hypr/hyprland.lua
dofile(os.getenv("HOME") .. "/.config/hypr/molvai.lua")

The generated file holds a pair for the hold and binds for the toggle, command mode and cancel. The cancel bind is non-consuming, so the key still reaches the application and a bare Escape keeps working elsewhere

hl.bind("F9", hl.dsp.exec_cmd("molva record start"), { description = "MolvAI: dictate while the key is held" })
hl.bind("F9", hl.dsp.exec_cmd("molva record stop"), { release = true, description = "MolvAI: paste the text on release" })
hl.bind("CTRL + ALT + Z", hl.dsp.exec_cmd("molva record toggle"), { description = "MolvAI: start or stop a recording" })

The GUI rewrites the file and reloads Hyprland when you change the hotkeys. Without the GUI, start the daemon from Lua: hl.on("hyprland.start", function() hl.exec_cmd("molva daemon") end)

Hyprland before 0.55

That version reads ~/.config/hypr/hyprland.conf. The hold pair is two lines, and bindr fires on the release

bind = , F9, exec, molva record start
bindr = , F9, exec, molva record stop

Sway

# ~/.config/sway/config — --no-repeat stops auto-repeat from restarting the recording
bindsym --no-repeat F9 exec molva record start
bindsym --release F9 exec molva record stop
bindsym --no-repeat Ctrl+Shift+space exec molva record toggle
bindsym --no-repeat Ctrl+Shift+Escape exec molva record cancel
exec molva daemon

KDE Plasma and GNOME

Neither reports the key release, so push-to-talk is impossible there and only the toggle works. Add molva record toggle as a custom shortcut in the system settings

path=/org/gnome/settings-daemon/plugins/media-keys/custom-keybindings/molva/
gsettings set org.gnome.settings-daemon.plugins.media-keys custom-keybindings "['$path']"
gsettings set org.gnome.settings-daemon.plugins.media-keys.custom-keybinding:$path name 'MolvAI toggle'
gsettings set org.gnome.settings-daemon.plugins.media-keys.custom-keybinding:$path command 'molva record toggle'
gsettings set org.gnome.settings-daemon.plugins.media-keys.custom-keybinding:$path binding '<Ctrl><Shift>space'

X11 without a desktop

sxhkd works, and so does the built-in keyboard capture: hotkeys.backend = "evdev". The evdev backend needs permission to read the input devices; after you add the group, log in again

Windows and macOS

The application registers the global combination itself, so the system needs no bind. On macOS grant the Accessibility and Input Monitoring rights, without which the global keys and the paste do not work

If a bind does not fire

Run molva doctor. It prints the session, the compositor, the paste utilities it found, the availability of /dev/uinput and /dev/input, and whether the daemon answers on the socket. The most common cause of a silent bind on NixOS is a molva missing from the PATH of the environment that starts the bind

molva doctor
