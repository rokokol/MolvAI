Models and GigaAM

Canonical source: models.toml and docs/model-licenses.md

What a model is here

One weights file and one entry in models.toml. The entry carries the name, the file name, the download address, the size, the SHA-256 and the engine that can load the file. The CLI, the GUI and the Nix module read that one list, so a name means the same thing everywhere

The default

The default is gigaam-v3-e2e-rnnt-q4_k_m: GigaAM-v3 end-to-end RNNT from Sber, at Q4_K_M quantization, 175 MiB, Russian. The default engine is auto

The default, as the catalog declares it
FieldValue
Namegigaam-v3-e2e-rnnt-q4_k_m
Filegigaam-v3-e2e-rnnt-Q4_K_M.gguf

Languageru
Size183,948,704 bytes, 175 MiB

The full catalog, with sizes and quantization for every file, is on the model catalog page

Why the CPU-first default

Russian dictation is the main case, and the CPU is the hardware every machine has. GigaAM is a Russian-first family, and the Q4_K_M file keeps the model small enough to load quickly and to sit beside other work

transcribe.cpp publishes a benchmark of this quantization on a Ryzen 7 4750U: 10.98 s of audio in 630 ms, about 17× realtime. The same run reports about 15.5× on a 33.84 s clip

That is an upstream measurement, not this project's. No GigaAM GPU figure is published in the repository

The engine

What stt.engine accepts
ValueMeaning
autoFollow the catalog entry of the model. This is the default, and it is why a GigaAM file needs no special setting
whisper-cppThe whisper.cpp runtime. It reads the ggml files of the catalog and your own whisper weights
transcribe-cppThe transcribe.cpp runtime, which loads the GigaAM GGUF file. stt.transcribe_cli names the binary; empty means transcribe-cli from PATH
fakeA test engine that returns fixed text. It runs the pipeline without weights

The GPU path belongs to whisper.cpp: the released Linux and Windows builds use Vulkan. A CUDA build is a separate opt-in, and the releases carry it for Windows. stt.transcribe_backend passes auto, cpu, vulkan or cuda to transcribe.cpp

Download, verify, switch

molva models list
molva models pull large-v3-turbo
molva models verify large-v3-turbo
molva config set stt.model large-v3-turbo

Every download is checked against the SHA-256 from the catalog before it reaches the disk. A daemon start pulls missing weights on its own while stt.auto_pull is true, which is the default. The recognizer is built when the daemon starts, so restart the daemon to load different weights

Mirrors and your own weights

stt.models_mirror points at a directory that serves the same file names instead of Hugging Face. The checksum check still runs, so a plain http:// mirror on a local network is acceptable

Your own file goes through stt.model_path, the directory that holds the weights, and stt.model, the name the engine sees. A ggml file that whisper.cpp understands fits the whisper engine

Licenses

The repository is MIT and the weights are not covered by that license. Their terms are collected in docs/model-licenses.md, and the addresses they come from are part of docs/outgoing-endpoints.md

With Nix

The Home Manager module fetches the models named in programs.molvai.models at evaluation time and renders stt.model_path into the store as a directory of symlinks. A switch is the only thing that changes them. programs.molvai.model must be one of programs.molvai.models, and an unknown name fails the switch with a message that names the option
