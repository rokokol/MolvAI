Troubleshooting

Canonical source: README and WORKAROUNDS.md

Start with the doctor

One command names the broken part and the next step. It checks the session, the compositor, the paste utilities and the permissions on the input devices. It also checks the daemon socket, the weights and their checksum, and the model provider

molva doctor

If the problem is about a phrase that seems to vanish, follow the daemon while you dictate

molva status --watch

Symptom, cause, fix

The failures people meet first
SymptomLikely causeWhat to do
A bind does nothingmolva is not in the PATH of the environment that the compositor uses to start the bind, which is the usual NixOS causeRun molva doctor, then call the binary by its absolute path in the bind
Push-to-talk records for a moment and stopsThe desktop does not report the key releaseUse the toggle on KDE and GNOME, the hold on Hyprland and Sway, or the evdev backend
The recording is empty or the level is zeroA wrong device or a muted channel in the mixer, not a quiet voicePick the device from molva devices, write it to audio.device, check the mixer
Nothing appears in the fieldThe compositor refuses input emulation, or wtype is missing on WaylandInstall wtype, run molva test-inject, and fall back to output.mode = "clipboard"
The paste lands in the wrong placeThe focus has not returned to the field yetRaise output.pre_inject_delay_ms; on a remote desktop it needs up to 1500
The terminal pastes the wrong thingTerminals want Ctrl+Shift+VLeave output.terminal_shortcut = true, which is the default and detects the window class
Exit code 3The daemon does not answer on the socketStart molva daemon, check molva status, check --socket and MOLVA_SOCKET
Exit code 4The previous phrase is still being processedWait for it. A new recording is otherwise allowed while the previous one is recognized
Exit code 7A daemon of the same user already runsUse the existing instance; only one owns the microphone
The weights are missingNo file in the models directory, and the automatic download is off or failedmolva models pull gigaam-v3-e2e-rnnt-q4_k_m, or point stt.models_mirror at a local directory
A checksum does not matchA truncated download or a mirror serving another filemolva models pull <name> --force, then molva models verify <name>
The language lands on Ukrainian or BulgarianAutomatic detection on a short Russian phraseKeep stt.language = "ru", or restrict allowed_languages
The language model returns an empty textA reasoning model spends the token budget on reasoningLeave llm.reasoning_effort = "auto", which sends none to local providers
The model is slow to answerThe timeout passed, so the text after the rules was usedRaise llm.timeout_secs, or disable the model for that style
Command mode reports no selected textNothing is selected, or the copy combination did not reach the applicationSelect the text first, check the compositor shortcut, and read the log line of the copy
A runtime setting disappeared after a rebuildThe rebuild changed the declarative config and dropped the overrides in runtime.tomlPut a permanent value in programs.molvai and run the switch
The GUI asks to build molvaA release whose GUI package shipped without the CLITake the CLI archive of the same release, or read the notes of the release you installed

Collect the facts before you ask

  • The output of molva doctor and molva --version
  • The session type and the compositor: echo "$XDG_SESSION_TYPE" and echo "$XDG_CURRENT_DESKTOP"
  • The settings as they are loaded: molva config get
  • The error field of the phrase in the journal, from molva history show <id>

With those facts, an issue can be answered without a round of guesses. The project's issue tracker is github.com/rokokol/MolvAI/issues

Known limits are not bugs

Pre-roll audio is deliberately not captured, and GNOME and KDE cannot report a key release. A whole English sentence inside a Russian phrase is not read as English either. The status page and CHANGELOG.md list the rest
