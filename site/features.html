Features

Dictation first, and the small things around it

MolvAI is one pipeline with one storage file. Each feature below is a setting of that pipeline, not a separate service. Where a feature has a limit, the limit is named too

MIT Local CPU first Wayland · X11

Snippets, the main thing

Say three words, get the whole answer

Dictation saves typing. A snippet saves more: you say a short phrase and the field receives text you wrote earlier. It returns before the model, so it waits for no call, spends no tokens and works with the cable out

You sayreply to the client

The field getsHello! Thank you for getting in touch. I will answer within the working day.

You saycall *

The field getshttps://meet.example/team — the standing link for the call

You saymy address

The field getsKazan, Baumana street 1 — entrance 2, floor 3

  • Only the whole phrase matches: a phrase that merely contains the trigger does not fire
  • Case, punctuation and extra spaces do not matter
  • * matches any tail, including none, but adds nothing to the replacement
  • An exact phrase wins over a wildcard, so a broad pattern never hides a specific answer
  • The replacement is final: no style, no model and no rule rewrites it
  • A phrase of nothing but * is refused, because it would replace every dictation

Snippets live in [snippets] of the settings file, in the Snippets tab of the window and in molva config set. A matched phrase is marked in the journal by the snippet field, so the count of answers that came without the model is visible

The rules, wildcards and limits →

Dictation

From a held key to a finished sentence

The microphone is the hard part of a dictation tool, and most of this list is about closing it at the right moment

Any application

The text goes into the field that has the focus: an editor, a chat, a terminal, a browser form. The paste method is chosen automatically and the journal records which one worked. In a terminal the shortcut switches to Ctrl+Shift+V

Hold, tap or cancel

Hold F9 to dictate while the key is down. A short tap latches the recording, and the next tap ends it. Ctrl+Alt+Z toggles from anywhere, Ctrl+Alt+C throws the recording away. Every combination is a setting

Text while you speak

With stt.chunked the phrase is cut at short pauses and each chunk is recognized during the recording for the draft. The field receives the text as one piece after the release: live chunk typing is off until its own follow-up work

Two recordings never collide

The next phrase records while the previous one is recognized. The daemon counts the phrases in processing and goes back to ready after the last one. Exit code 4 appears only when the previous phrase truly blocks the request

Text quality

Cleanup without a model, a model when you want one

The default pipeline is deterministic: a term dictionary and a rule set. No token leaves the machine unless you turn the model on

Dictionary and rules

Your names and product terms are substituted fuzzily. Spoken punctuation becomes punctuation, filler words disappear, repeats collapse, numerals become digits. The rules run in milliseconds and are covered by the same tests as the rest

Optional language model

Off by default. When on, it speaks the OpenAI-compatible protocol and Ollama is the default provider. It runs only for styles that need it, when the phrase reaches that style's word minimum. A timeout returns the text after the rules, never an empty field

Styles

The same voice, three different texts

A style decides what happens to the text after the rules. It also decides whether the model is called: As spoken never calls it, so it works offline and costs nothing

No model

As spoken

The dictionary and the rules, and nothing else. Not one token, no network, no wait for a call. The style for anyone who wants exactly their own words

Model

Cleanup

Punctuation, case and recognition errors are fixed, slips and fillers removed. Every other word, the meaning and the terms stay. The default style out of the box

Model

Formal

Formal business style: full sentences, no colloquial turns, contractions or emotion. For letters and documents, not for a chat

A style per application

style.by_app maps a window class to a style: Cleanup in a messenger, Formal in mail, As spoken in a terminal. The window class comes from the compositor, so a rule also covers applications you did not configure one by one

Your own styles and a word minimum

A custom style is a name, a prompt and a word minimum. A phrase shorter than the minimum skips the model: a short "yes" is not worth a call. The built-in minimum is three words, and each style sets its own

molva styles list

molva styles list prints the identifier, the name, whether the model is needed and the word minimum. Switching on the fly is molva styles next or the hotkeys.style_next combination

Voice editing

Select a paragraph and say what to do with it

A style rewrites what you dictated. Voice editing rewrites what is already written: select text, say the instruction, and the selection is replaced with the result. This is the project's original feature, and it needs a model

SelectedHi, how are you? The call moved to tomorrow.

You saytranslate to German

The selection becomesHallo, wie geht es dir? Der Anruf wurde auf morgen verschoben.

SelectedThe call moved to tomorrow. Do not forget the documents.

You sayadd emoji

The selection becomes📅 The call moved to tomorrow. 📄 Do not forget the documents.

  • Ctrl+Alt+X by default: hold, say the instruction, release
  • An instruction is an ordinary phrase, not a command from a list: "translate to German", "add emoji", "make it shorter"
  • The model returns the text only: no headings, markdown or explanations, and no facts it was not given
  • The result takes the place of the selection, and Ctrl+Z brings the old text back

Files and search

Your recordings become text you can search

A transcription of a file lands in the same journal as a dictated phrase, so one search looks at both

Audio and video, with timecodes

The window sends the file to the daemon over IPC and gets the text with timecodes from the same recognizer as dictation. molva transcribe --timecodes has its own job: an offline batch from a path, a directory, a nested tree or a stream on stdin, --json for machines, and one bad file does not cancel the batch

molva transcribe talks/ --recursive --timecodes

Search across transcripts

Every transcription lands in the same journal. molva search finds a phrase in any of them and prints the source file with a MM:SS.mmm timecode. There is no second index to fall out of date

molva search "release date" --since 7d

Journal and statistics

One JSON line per phrase: text, words, words per minute, style, engine, model, dictionary hits, the paste method and the latency of every stage. molva stats turns it into averages, a personal record and a daily picture

History that comes back

molva history paste --last puts the previous phrase into the field again without a second dictation. Filters by app and time, export to JSONL or CSV, delete one line or clear all of it

One process

One daemon, any number of clients

Dictation, file transcription and the MCP server share one recognizer, so no second copy of the weights sits in memory

A warm recognizer for a file

Files sends a file.transcribe request to the daemon over IPC. The model, the language, the dictionary and the rules are the ones dictation uses, and the window starts no second process. molva transcribe stays a separate command for an offline batch

A file never takes the microphone

While a file runs, the state stays idle and the job field says file, which the panel and molva status report as a file transcription. A recording during a file is accepted and waits in the queue. A file during a recording gets a busy answer: the CLI reports exit code 4, and the window keeps asking for up to half an hour

MCP without a port

molva mcp speaks over stdio: no URL and no autostart. It starts the daemon when nobody answers and then uses its model. mcp.enabled turns the server off

Cloud in parallel, local in turn

A cloud provider may answer four calls at once, and a local model takes requests one by one, because two at once answer worse. One place holds that policy, so no stage waits beside another on its own

Privacy and portability

Local by construction, not by a setting

The parts that would need a server are the parts that have a local first choice

Microphone discipline

The device opens on the press and closes on the release. The close does not depend on how the phrase ended, and its delay is measured and journaled

Encryption and no-record mode

The journal texts can be sealed with XChaCha20-Poly1305 and a key in the OS store or a 0600 file. The statistics keep working without the key. No-record mode writes nothing at all

Offline

Only the weight download and a cloud model provider use the network, and both wait for your command or your configuration. Everything else works with the cable out

Nix first

The flake gives a dev shell, a package and a Home Manager module. The module renders the settings file and the weights into the store, runs the daemon as a user service and writes the Hyprland binds. The settings stay editable at runtime, and a change stays until a rebuild changes the declarative config

Other systems

Ready builds exist for Linux, Windows and macOS, and the installer checks dependencies instead of installing them. The paste chain falls back to the clipboard when the compositor refuses

Model choice

GigaAM-v3 by default, whisper.cpp models when you want them. Downloads are checked against a SHA-256 from the catalog, and stt.models_mirror serves the same file from a local network

Limits

What it does not do yet

The project is in development. A feature list without a cut list is marketing, so the cut list lives in the open

Read the status page before you rely on a feature

Known gaps include the Windows and macOS checks on live hardware, which the repository marks as unverified. The releases carry optional CUDA archives for Windows and Linux. The release history is in CHANGELOG.md, summarized on the status page

Speech in the middle of a phrase

A whole English sentence inside a Russian phrase is not read as English. Latin insertions and terms work, and the language is chosen once per phrase

Pre-roll audio

The first syllable you say before the microphone opens is lost. A pre-roll needs a permanently open stream, and this project keeps the microphone closed
