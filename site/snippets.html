Snippets

Say three words, get the whole answer

A snippet is a pair: the phrase you say and the text that must land in the field. You save the pair once. After that a short phrase returns a long text, and it returns before the model: with no wait for a call, no tokens and no network

No model No tokens Works offline Wildcards

Examples

What you say and what you get

The three pairs below are the real settings format, not an illustration. The first matches exactly, the second by wildcard, the third returns a long text for a short phrase

You sayreply to the client

The field getsHello! Thank you for getting in touch. I will answer within the working day.

You saycall *

The field getshttps://meet.example/team — the standing link for the call

You saymy address

The field getsKazan, Baumana street 1 — entrance 2, floor 3

[snippets]
enabled = true

[[snippets.items]]
phrase = "reply to the client"
replacement = "Hello! Thank you for getting in touch."

[[snippets.items]]
phrase = "call *"
replacement = "https://meet.example/team"

[[snippets.items]]
phrase = "my address"
replacement = "Kazan, Baumana street 1"

The same file is edited in the Snippets tab of the window and by molva config set. Under Nix the declarative file stays in the store, and edits from the window go to runtime.toml beside it

The rules

When a snippet fires, and when it does not

The rules are short, and each one follows from a single thought: a snippet replaces a whole phrase, not a piece inside one

The whole phrase only

The phrase "reply to the client please" does not fire the snippet "reply to the client": it contains the trigger but is not equal to it. Otherwise a snippet would eat half of a dictation

Case and punctuation do not matter

The recognizer writes "Reply to the client." with a capital and a full stop, and the person means the same phrase. So the comparison runs over words: lower case, "ё" as "е", no punctuation and no extra spaces

A wildcard changes the trigger only

* matches any tail, including none: "call", "call at three", "call tomorrow" all give the same link. The wildcard adds nothing to the replacement: the text is static and there are no variables

An exact phrase wins over a wildcard

With both "call *" and "call at three", the second fires on "call at three". A broad pattern never hides a specific answer. Among wildcards the first in the list wins, and duplicates are refused when the settings are checked

The replacement is final

No style, no model and no rule rewrites the replacement. A prepared answer is already the text that must land in the field, and any edit after it would be a mistake

A phrase of nothing but * is refused

Such a pattern would replace every dictation with one text. The settings check refuses it, and refuses an empty replacement too

Where it lives

Three places, one file

The settings file is the single source of truth. The window and the CLI edit that same file, so the two cannot disagree

The settings file

The [snippets] section: enabled and a list of items of phrase and replacement pairs. molva config path prints both paths: the declarative one and the runtime one

The tab in the window

The Snippets tab shows the cards and lets you edit them, filter by phrase or replacement, and check for duplicates before saving

The command

molva config set snippets.enabled true and molva config reload apply an edit to the running daemon without a restart

molva config set snippets.enabled true

A matched phrase is marked in the journal by the snippet field, so molva history and the statistics show how many answers came without the model

Limits

What a snippet does not do

A feature list without a list of limits is marketing. The limits below are properties of the design, not loose ends

No variables

A wildcard decides what triggers the snippet, not what lands in the text. You cannot put a client's name or a date into the replacement: that needs a model, and a snippet exists precisely to avoid calling one

Not everywhere

Snippets work in dictation. Voice editing, file transcription and a phrase typed in chunks do not use them: the first two have no "whole phrase" in the sense a snippet expects, and the third has already put text into the field piece by piece

A list, not a database

Snippets live in the settings file and are checked on load. Hundreds work, tens of thousands do not: this is a list of prepared answers, not a search index

Only after the dictionary and the rules

A snippet is compared with the text after the dictionary and the rules, not with the raw recognizer output. That way "ё" and spoken punctuation do not break a match, but a dictionary edit can change what fires
